# 运行示例：EndlessSpace 真机四域修复（Device Parity）

这是一个**取自真实项目**的完整运行示例，用来演示「Agentic Workflow 标准」如何把一个模糊目标，落成**可并行、可验收、不撞车**的任务网络。

## 背景

**EndlessSpace** 是一款太空策略游戏的原 iOS 工程（Swift + SpriteKit）。项目决定用 **Godot 4 复刻**一套跨平台正式版，要求「与 Swift 版一比一迁移」。仓库里两套实现并存：`EndlessSpace/`（Swift 真源）与 `Godot/`（复刻版）。

某天用户拿 **iPhone 真机实测**，一次性报回四类问题：

- **SHIPYARD**：三栏整体错位，energy 条压到橙色分隔线下，舰级标签快掉出卡片；
- **EQUIP**：三栏全空，显示 `LEGACY SAVE IMPORT FAILED`；
- **BATTLE**：舰船/UFF 环/HUD 三套比例互不一致、完全没开火、无星系背景；
- **TECH**：图标错误、滚动抖动。

根因不是单点 bug，而是三类系统性债务（**布局模型**用硬编码常量 vs Swift 比例推导、**数据层** legacy 导入失败即阻塞整页、**比例/资产**各用一套系数）。团队据此制定了「真机实测四域修复计划」，本示例就是该计划的可复用骨架。

## 本示例演示框架的哪几章

| 框架环节 | 本示例文件 | 演示内容 |
| --- | --- | --- |
| **功能域树建模** | `domains.json` | 把整个产品面建成树：16 个一级域，`battle` 深挖到 3 级；叶子节点遵守「≤3 文件 + 唯一验收」停止规则 |
| **模糊目标 → 影响域树状搜索** | `tasks.md`（开头的「任务解读」） | 从「一比一迁移」这个模糊目标，逐步收窄到 TECH/SHIPYARD/EQUIP/BATTLE 四个真机有差异的域 |
| **任务拆解与完成标志** | `tasks.md`（P1–P4 六列表） | 每个子任务带 `真源 / 落点 / 完成标志 / 改动文件`；这里的 `L0/L1/L2` 是**本项目自定**口径，非框架要求（框架只提供可选留痕格式） |
| **文件所有权矩阵** | `ownership-matrix.md` | 按**文件**聚合出串行链，识别全局共享热点，给出并行度上限 |
| **跨域并行波次** | `waves.md` | W1–W8 波次排布，逐波证明「波内零文件重叠」 |

## 最重要的三条教训

### 教训 1：并行轴选错——按「功能域」分批，导致同域并行度 ≈ 1

初版把批次轴定成「功能域」（P1=TECH、P2=SHIPYARD…），再要求「每批 ≥10 并行」。这是**根本性错误**：一个功能域在文件层面往往只有 1 个文件——TECH 的 12 个任务里 10 个都改 `tech_view.gd`，SHIPYARD 的 12 个里 7 个都改 `shipyard_view.gd`。同一文件同一时刻只能被一个 agent 写，所以**同域真实并行度 ≈ 1**，「≥10 并行」被写在了错误的轴上。

正确做法是：**并行切片要跨域取，不能同域取**（跨页面撞车概率远低于同页面）。在文件系统里，资源的容量单位是**文件**，并行调度必须建在文件之上。

### 教训 2：Agent 违规拉分支/worktree 且不提交，根因是规范自相矛盾

执行中出现 agent 大量私拉分支/worktree、子任务做完不提交、跨任务堆积的现象。复盘发现**根因不在 agent，而在规范自相矛盾**：早期文档一边说「默认单主干直推、完成即 commit」，一边又鼓励「开 worktree 并行」，两套规则打架，agent 无所适从。

修正为**混合模型**并写死硬约束：默认单主干直推；只有「体量大且文件完全独立」才开短命 worktree，且**完成即当天合入主干并删除**（生命周期以小时计）；子任务做完即 `git add <具体文件>` 提交，**禁止跨任务堆积**。**规范必须先自洽，再谈执行。**

### 教训 3：矩阵必须回到真实文件核对——初版 BATTLE 链数误判

初版矩阵凭目录名想象，把 `presentation/tactical_hud/*` 当成**一条链**、把雷达单列，且把路径写成 `presentation/tactical/*`。回到真实文件核对后发现全错：

- `tactical_3d_layer.gd` / `tactical_camera_mapper.gd` 实际在 `presentation/helios/`，**`presentation/tactical/` 目录根本不存在**；
- 右上五按钮（SHIPS/FLEET/TECH/RETREAT/MAP）是 `battle_radar_view.gd` 里的 affordance，与 P4-9 雷达**同文件**；
- IFF 环实际画在 `world_feedback_layer.gd :: _render_iff`，**不是** `tactical_3d_layer.gd`。

结果：初版误判 BATTLE 只有 ~4 条并行链，细粒度切分后**实为 10 条链**。**矩阵必须逐文件核对，不能凭目录名推测。**

## 结论

> **并行度上限 = 独立文件链数。**

本示例中独立链数为 T=1 + S=1 + S′=1 + E=4 + B=10 = **17 条**，对应 W1 的 17 并发峰值；随着各链被占用，波次并发依次收缩（17→5→4→4→2→2→1→串行）。想提高并行度，唯一的办法是**把工作切到更多互相独立的文件**，而不是在同一个文件上堆更多 agent。
