Trae 车道接入

让 Trae CN 的 IDE agent（如 DeepSeek-V4.1-Flash）和 Codex / Claude 一样挂在文件总线上：收到消息自动开工，干完用 bus.py 回信。

实测环境：Trae CN 3.3.104 · macOS · SOLO agent + DeepSeek-V4.1-Flash · 往返 #872 → #873

问题与结论

Trae 没有公开的 API 或 CLI 能让外部脚本叫醒它的 agent。trae-cn 命令只是 VS Code CLI 换皮。

突破口：Trae CN 内置了「飞书 / 微信 IM 桥」（cloudide.icube-im-bridge），手机上发的消息就是靠它投进 agent 会话的。它在工作台注册的内部命令 im.bridge.handleIncomingMessage，任何扩展都能调用。

所以我们写了一个约 40 行的本地扩展 trae_bridge/：开一个 unix socket，收到文本就调这个命令。bus_wake.py 把它当作第三种唤醒通道。

厂商唤醒方式空闲检测文档
Codex共享 app-server daemon，turn/start有setup_codex
Claude Code会话收件箱 socket有setup_claude
Trae CN本地扩展 → 内部 IM 桥命令无，由 Trae 自己排队本页

原理

bus.py send --to trae-1
  └─ 自动调 bus_wake.try_wake(trae-1)
       └─ trae_agent()：ping ~/.trae-cn/agentic-bridge.sock，确认 Trae 窗口打开的是本仓库
       └─ trae_call({"wait": false, "text": 唤醒文案})
            └─ [Trae 扩展宿主] local.agentic-bus-bridge
                 └─ vscode.commands.executeCommand("im.bridge.handleIncomingMessage",
                        {channel:"feishu", text, messageId:"bus-…", sentAt})
                      └─ [工作台] 文本作为用户消息进入 Trae 当前 agent 会话（聊天面板可见）
Trae agent 读 AGENTS.md（经 .trae/rules/project.md 转发）→ bus.py read / 干活 / bus.py send 回信

socket 协议是一行 JSON 请求、一行 JSON 回复：

请求作用
{"op":"ping"}返回 {"ok":true,"busy":false,"workspace":[…]}，用来做在线检测和仓库匹配
{"wait":false,"text":"…"}投递消息（正式通道）
{"op":"exec","cmd":"…","args":[…]}调试用：执行任意 Trae 命令并返回结果，例如 icube.chat.getCurrentSessionId
{"text":"…"}走 feishu.bridge.sendAndWaitResponse。SOLO 模式下无效，见坑 1

接入步骤

  1. 安装扩展：
    bash agentic_workflow/trae_bridge/install.sh
    脚本把 package.json 和 extension.js 拷到 ~/.trae-cn/extensions/local.agentic-bus-bridge-0.0.1/，并登记进 ~/.trae-cn/extensions/extensions.json。
  2. 在 Trae 里打开仓库根目录（EndlessSpace/，不是子目录），开一个 agent 对话，选好模型。
  3. Cmd+Shift+P → Developer: Reload Window，扩展会在 onStartupFinished 时激活。
  4. （可选）改 agent ID：往 .agentic/bus/trae_agent.txt 写一行，例如 trae-2。默认是 trae-1。

验证往返

ls -l ~/.trae-cn/agentic-bridge.sock              # 扩展已激活
python3 agentic_workflow/tools/bus_wake.py list    # 出现  trae  trae-1  …
python3 agentic_workflow/tools/bus.py send --from <我的ID> --to trae-1 --type PROPOSE \
  --body "连通测试：用 bus.py 回我一条 ACCEPT，body 写你的模型名，不要改文件。"
python3 agentic_workflow/tools/bus.py read --agent <我的ID> --unread   # 约 1 分钟内收到 trae-1 的 ACCEPT

Trae 聊天面板里会看到这条唤醒文案作为用户消息出现，agent 随即开始跑。

日常使用

  • 在计划源文件的车道表里给 trae-1 分车道，规矩和 Codex / Claude 完全一样（claim → 干活 → done，走总线）。
  • 点对点 bus.py send --to trae-1 发送时就会叫醒；广播和巡检靠 bus_wake.py watch 轮询。
  • 手动叫一次：bus_wake.py wake --agent trae-1（按收件箱新消息投递）或加 --text "…" 发自定义文本。
  • Trae 没有回调，看它在干什么只能看 Trae 面板、它的总线消息和 task_state.py log。

坑

1. feishu.bridge.sendAndWaitResponse 在 SOLO 模式下立即返回空
它名字看着最合适（发消息并等回复），但实测立刻返回 {"text":""}，日志里也没有动作。要用 im.bridge.handleIncomingMessage（IM 桥真实的收消息路径）。
2. 没有空闲检测
工作台里找不到暴露「会话是否在跑」的命令（相关逻辑在 xc 服务内部，扩展拿不到）。所以每批新消息只投一次（推进 wake_state.json 游标），Trae 忙时由它自己的消息队列（AI.soloLite.messageQueue）排队。不要把 watch 间隔调得很短来「补叫」，会刷屏。
3. 只能投到 Trae 当前选中的会话
目标由 Trae 自己决定，扩展指定不了会话。所以一个 Trae 窗口只接一个 agent；切换聊天会话后，消息会去新会话。
4. trae-cn --install-extension 会失败
Trae 正在运行、又曾删过同名扩展目录时，会报「Please restart VS Code before reinstalling」。install.sh 因此直接写扩展目录并改 extensions.json，再 Reload Window 即可。
5. 仓库匹配是严格相等
trae_agent() 要求 ping 返回的 workspace 里有仓库根的绝对路径。Trae 打开的是子目录（如 agentic_workflow/）就不会被发现。
6. 后台 watch 进程要重启
改了 bus_wake.py 后，已经在跑的 watch 仍是旧代码。点对点 send 不受影响（每次都新起进程），但轮询叫醒要重启 watch 才生效。
7. 扩展改动要 Reload Window
改 extension.js 后要重跑 install.sh 并 Reload，这会打断 Trae 正在跑的对话，挑空闲时做。
8. agent ID 规矩照旧
裸 trae 会被 task_state.py 拒绝，必须写 trae-1 这类带实例号的 ID。Trae 读 .trae/rules/project.md，它只做转发到 AGENTS.md，不要在里面写第二份规矩。

调研过、没采用的方案

方案为什么没用
字节开源 bytedance/trae-agent（trae-cli run）能无界面跑，但不是 IDE 里的 agent；DeepSeek 得用自己的 API key 付费，用不了 Trae 内置额度
trae-cn chat -m agent "…"VS Code 原生命令，大概率打开的是 VS Code 聊天面板而不是 Trae 的 AI 面板，也拿不到结果
trae-cn:// 深链只有打开文件之类的标准链接，没有「带提示词打开聊天」
AppleScript 模拟键盘输入聊天框要辅助功能权限、窗口必须在前台，UI 一改就坏
MCPMCP 只能被 agent 调用，不能主动叫醒空闲 agent
trae2api 之类代理额度的项目冒用登录态，违反条款，有封号风险

Trae 升级后怎么修

症状：bus_wake.py list 看不到 trae，或者投递返回 ok 但面板没反应。按下面的顺序排查：

W="/Applications/Trae CN.app/Contents/Resources/app/out/vs/workbench/workbench.desktop.main.js"
grep -oE '"im\.bridge\.[a-zA-Z]+"' "$W" | sort -u        # 命令还在吗、改名了吗
grep -oE 'id:"[a-zA-Z0-9_.]*(chat|session|solo)[a-zA-Z0-9_.]*"' "$W" | sort -u   # 有没有新的会话/状态命令
grep -rh "local.agentic-bus-bridge" ~/Library/Application\ Support/Trae\ CN/logs/*/ | tail   # 扩展有没有激活

命令改名就改 trae_bridge/extension.js 里的命令 ID，重跑 install.sh 再 Reload。如果新版出现了查询会话状态的命令，可以给 bus_wake 补上空闲检测，解决坑 2。
