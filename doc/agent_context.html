Agent 的记忆与知识管理

我们已经有了一套很棒的框架，但它是不是在新窗口里"自动生效"？一份文件到底是每次必读、读一次就够、还是碰运气才被读到——这篇把它彻底讲清。

2026-10-05 · 覆盖 Codex / Claude Code / Trae（附 Cursor / Copilot / Gemini 对照）· 实例：EndlessSpace

0问题：新开一个窗口说"去做 P1-3"

先把你的三个疑问摆到桌面上：

① 新开一个 Codex 窗口，我只说一句「你去解决任务 P1-3」，它能不能知道我们定过的这套规矩（单主干、验收铁律、文件所有权矩阵、task_state.py……）？
② 项目里躺着 AGENTS.md、CLAUDE.md、README.md —— 到底哪些是每次必读？哪些是读一次就够？哪些是偶尔才被读到？
③ 这些文件里，哪些是 Codex 读但 Claude 不读？Trae 又读哪些？

答案的关键，是先破除一个直觉："文件在仓库里" ≠ "agent 会看到它"。一个 agent 每次开工时，脑子里（上下文窗口）装着什么，是由三个不同的机制分别灌进去的，而这三个机制的"读取时机"和"可靠性"完全不同。下一节先建立这根主轴。

1主轴：上下文在什么时机进入

不看厂商，先看机制。一个 agent 的上下文窗口，内容来自五层，按"进入时机"可以归成三类：

记住这张图的分类：A 启动自动 B 触发按需 C 自主/引用 D 记忆。下面所有厂商机制，都是在回答"某类文件被归到了哪一档"。

最反直觉的一条：README.md 对任何一个 agent 都不是指令文件。它既不会被自动注入，也不是"必读"。它是写给人看的说明；agent 只有在自己决定去读、或你显式引用时才会看到它。把规矩写进 README 指望 agent 遵守，是最常见的误解。

3四类"读到程度"分类学

回到你的原话，我把它翻译成精确的机制问题。你问的三档，其实是四档：

① 每次工作都会读（A 类）

启动时自动注入会话，整个会话常驻。但它只 读一次——不是每一轮都重新读文件。改了文件要新开会话才生效。
例：AGENTS.md（Codex）、CLAUDE.md（Claude）、alwaysApply 规则（Trae）。

② 读一次、之后同窗口不再读（A/B 类的"memoized"）

这是 A 类的实现细节：内容在会话启动读一次并缓存；会话压缩（compact）后会被重新读一遍。
另一类：子目录的 CLAUDE.md——agent 第一次读到该子目录的文件时才载入，之后缓存。

③ 优先但"不一定读到"（B 类）

启动时只载入标题/描述/触发条件，正文只在条件命中或被调用时才进上下文。
例：技能（skill）的名字+描述；Trae 的 globs/智能生效规则；Claude 的 path-scoped rules。

④ 完全靠它自己决定（C 类）

没有任何机制保证它被读——agent 只有主动搜索或你显式引用时才看到。
例：README.md、Doc/**、计划文档、HANDOFF、events.jsonl。

一句话记法：只有入口文件（AGENTS.md / CLAUDE.md / rules）是"每次必读"。其余所有文档都是"读了入口、顺着入口被指过去"才会被读。入口文件是门，其它文件是门后的路。门若没写"去读 X"，agent 大概率不会走那条路。

4Codex 的机制：AGENTS.md 指令链

Codex 每次启动时构建一次"指令链"（instruction chain），把沿途找到的 AGENTS.md 拼成一段文本，塞进本次会话第一条消息的最前面——先于你的任何提问。启动后不再动态加载。

对你三个问题的直接回答（Codex 侧）

  • 必读？是。仓库根 AGENTS.md 会在每次启动时自动拼入，无需你提醒。但只在会话启动读一次。
  • 读一次不重读？是。启动即定，运行中不变。你改了 AGENTS.md，当前窗口不会感知，要开新窗口。
  • 不一定读到？是，除 AGENTS.md 外的一切文档（CLAUDE.md、Doc/**、README.md……）。注意 Codex 默认不读 CLAUDE.md，除非在 config.toml 用 project_doc_fallback_filenames 把它列为回退名。
  • 还有一层"记忆"：Codex 会在后台把过去的会话总结成 ~/.codex/memories/，下次会话读入。它不由你直接编辑，属于 D 类。

5Claude Code 的机制：CLAUDE.md 四层级

Claude Code 与 Codex 最大的结构差异：它的入口是 CLAUDE.md，且有明确的层级与导入机制。

Claude Code 还有一层 auto memory：它会把你在会话中的纠正、偏好自动记到 ~/.claude/projects/…/memory/，供后续会话使用——这就是你机器上 /Users/yuxuan/.trae-cn/memory/ 那套"记忆"的同类物，与"指令文件"是两回事。

6Trae 的机制：规则 + 四种生效方式

Trae 的入口不叫 AGENTS.md，而是 规则（Rule），分全局与项目两级，并且每条规则可单独指定生效方式——这比 Codex 的"整文件注入"更细粒度。

此外，Trae 的对话输入框支持 # 指定上下文：#Rule（引用项目规则）、#File / #Folder / #Workspace / #Doc / #Past Chats 等——这属于手动把 C 类文件抬进本次会话的主要手段。

注意：Trae 不会自动读 AGENTS.md 或 CLAUDE.md。要让它遵守同一套规矩，得把内容放进 .trae/rules/（或 ~/.trae/user_rules），并设为 始终生效。

现状的四个坑

  1. 两份真源、内容已经分叉。AGENTS.md 与 CLAUDE.md 各写了一遍"协作与分支规范"（措辞还不一样）。改一处忘一处就是漂移——和你刚修的"计划文档状态漂移"是同一类病。
  2. Trae 现在读不到我们的规矩。.trae/rules/ 目录都没建。我（Trae）之所以"知道"这些，是因为我会主动搜 Doc/** 并读到了计划/交接文档——这是 C 类运气，不是保证。
  3. 计划文档与新任务状态真的"没入口"。task_state.py 和 .agentic/tasks/events.jsonl 刚建好，但 没有任何入口文件提到它们。除非 agent 恰好搜到，否则它不会用。
  4. Codex 默认看不到 CLAUDE.md。反过来 Claude 也默认看不到 AGENTS.md。我们的"运行与截图链路"只写在 AGENTS.md 里，Claude 侧的可见性靠运气。

9处方：单一真源 + 指针

问题的本质不是"文件放哪"，而是"门"与"门后的路"没有连起来。三条规则就能理顺：

规则一：一份真源，其余全是"指向它的一行"

把内容统一写在 AGENTS.md（各家都在向它收敛），然后让其它入口只做转发：

# CLAUDE.md  ← 全文只有这一行转发，不再复制内容
@AGENTS.md
# .trae/rules/project.md  ← Trae 侧，同样只转发
---
alwaysApply: true
---
项目全部规矩以仓库根 AGENTS.md 为唯一真源，开工前先读它，再按它指引读 Doc/** 与计划文档。

这样三家的"门"都通到同一间屋。改一处，处处生效；再不会出现两份规范分叉。

规则二：入口文件必须写"指针"，不能只写原则

AGENTS.md 里要显式列出"要去哪读、要跑哪个工具"，否则 C 类文件永远靠运气被搜到：

## 任务在哪、状态怎么查（硬性，开工前必做）
- 任务定义/验收/改动文件 → Doc/godot/plans/<批次>-*.md
- 任务真实状态（唯一真源）→ .agentic/tasks/events.jsonl
- 查状态：python3 agentic_workflow/tools/task_state.py --plan <计划> status P1-3
- 认领/推进/提交/验收：
    ... task_state.py claim/start/submit/done <任务ID> --agent <你的ID>
- 分派前查文件重叠：python3 agentic_workflow/tools/check_file_ownership.py P1-3 ...

把"工具的调用方式"当作规矩的一部分写进入口——这样 Codex 一启动就"知道有这把钥匙"。

规则三：把"必读"与"按需"分层摆放

  • A 类（放入口文件）：稳定的大原则——单主干、验收铁律、提交规范、指针清单。保持精简（Claude 建议 <500 行；Codex 默认上限 32 KiB）。
  • B 类（按需）：路径专属规则（改 Godot/presentation/** 才加载的布局约束）、技能（截图流程、双端对比 SOP）。
  • C 类（文档）：计划文档、HANDOFF、状态日志。靠"入口文件里的指针"被找到，而不是指望 agent 瞎搜。
这套处方与刚才修的状态漂移是同一个道理：状态要"单一真源 + 工具读写"；规矩也要"单一真源 + 入口指针"。两者都拒绝"同一事实写两遍、且没人负责同步"。

落地清单（建议顺序）

  1. 把 CLAUDE.md 收敛成 @AGENTS.md + 少量 Claude 专属内容（不再复制规范正文）。
  2. 新建 .trae/rules/project.md（alwaysApply: true），内容为"以 AGENTS.md 为真源 + 指针清单"。
  3. 在 AGENTS.md 增一节「任务与状态入口」，写上第 9 节的指针清单（含 task_state.py 用法）。
  4. （可选）给 Codex 配 project_doc_fallback_filenames，或在 AGENTS.md 顶部一行 @CLAUDE.md 反向兜底，消除入口盲区。
