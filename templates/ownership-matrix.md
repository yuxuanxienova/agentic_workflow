# 文件所有权矩阵模板（Ownership Matrix）

> 用途：在**分派任何并行子任务之前**，以「文件」为单位检测重叠。资源容量单位是**文件**，不是功能域——同一文件同一时刻只能有一个 owner。
> 输入：`task-breakdown.md` 的「改动文件」列。输出：可并行的波次（跨域切片）与必须串行的链。

---

## 一、视图 A：按文件分组（= 串行链视图）

> 同一文件（组）下的所有子任务构成**一条串行链**，只能顺序执行。

| 文件 | 所属子任务 | 性质(串行链/独立) |
| --- | --- | --- |
| `<path/to/hot_file.gd>` | `<ID-1>`, `<ID-2>`, `<ID-5>` | **串行链 `<链名>`** |
| `<path/to/helper.gd>`（由 `<ID-1>` 抽出/新建） | `<ID-1>` | 随串行链 `<链名>` |
| `<path/to/independent.gd>` | `<ID-3>` | 独立 |
| `<path/flows/*.json>` | `<ID-4>` | 独立 |
| `<out/evidence/...>` | `<ID-6>` | 证据（收口热点） |

**规则**：一条串行链 = 一个并行槽位。**并行度上限 = 独立链数**，且这些链必须来自**不同功能域**。

---

## 二、视图 B：分派前置核查表（硬性）

> 每次准备把若干子任务放进**同一波次**前，逐行填此表。**只有「处置」全部为「无重叠/已串行」的波次才允许分派。**

| 子任务 | 将改动的文件 | 与谁重叠 | 处置 |
| --- | --- | --- | --- |
| `<ID-1>` | `<path/to/hot_file.gd>` | `<ID-2>`, `<ID-5>` | 串行 |
| `<ID-2>` | `<path/to/hot_file.gd>` | `<ID-1>`, `<ID-5>` | 串行 |
| `<ID-3>` | `<path/to/independent.gd>` | 无 | 可并行 |
| `<ID-4>` | `<path/flows/*.json>` | 无 | 可并行 |

### 重叠判定口径

- 精确路径相同 → 重叠。
- 一方是目录 / `*` 通配，另一方落在其下 → 重叠。
- 存在重叠的文件**必须串行，或归给同一个 agent**，**不得并行**。

> 建议用脚本做机器校验：把准备同波并行的任务 ID 传给 `check_file_ownership`（`tools/` 提供）。两两出现同一文件即报冲突并**退出 1**；无重叠退出 0。**只有退出 0 的波次才允许分派。**

---

## 三、硬性规则

1. **有重叠必须串行或归同一 agent，不得并行。** 这是矩阵存在的唯一目的。
2. **热点文件在任何波次里都串行，且只在收尾集成时改。** 热点文件示例（按项目替换）：
   - 主场景 / 主入口：`app/main.gd`、`app/main.tscn`
   - 测试 runner：`tests/test_runner.gd`
   - 验收脚本：`tools/verify.sh`
   - parity 矩阵 / 冻结计数：`doc/parity-matrix.md`、`tools/*_cases_v1.json`
   - 项目配置：`project.godot`、`.gitignore`
3. **并行切片取「跨域」，不取「同域」。** 一个功能域在文件层面常常只有 1 个文件，同域并行度 ≈ 1；跨页面并行撞车概率远低于同页面并行。
4. **收口串行链**：多个域都要改同一热点（如 parity catalog）时，合并为一条**收口串行链**，放在最后一波顺序执行。
5. **矩阵先于分派**：未填完视图 B 就分派并行任务 = 违规。

---

## 四、矩阵出口条件（Checklist）

- [ ] 视图 A 已列出所有文件，且串行链/独立性质已标注。
- [ ] 视图 B 每行的「与谁重叠/处置」已填，无遗留空格。
- [ ] 波次内两两无文件重叠（脚本退出 0）。
- [ ] 热点文件已单独标出，且只安排在收口串行波。
