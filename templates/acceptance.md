# 三级验收模板（Acceptance L0 / L1 / L2）

> 用途：为每个子任务规定「做到什么程度才算完成」的最低证据。**L0 绿 ≠ 能玩**；交互/表现类任务必须过 L1，勾「完成」还须过 L2。
> 与 `task-breakdown.md` 的「验收门槛」列配合使用。

---

## L0 — 自动化测试（最低门槛）

**定义**：自动化测试/构建**真实退出 0**。

### 最低证据清单
- [ ] 完整测试命令原文（含隔离参数，如 `--user-dir`）。
- [ ] **真实退出码 0** 的记录（命令后紧跟 `echo $?` 或等价输出）。
- [ ] 覆盖到改动套件/注册项（改了套件注册必须本地真实跑绿再提交）。

### 红线（不得勾完成）
- ❌ **用管道掩盖退出码**：`test.sh | tail`、`... | tee`、`... | grep` 后的 `$?` 是管道末端命令的退出码，**不得**作为 L0 通过证据。
- ❌ 只跑局部单测却声称「全量绿」。
- ❌ 套件注册改了却没跑，或跑了但退出码非 0 仍提交。

---

## L1 — 真实场景渲染 + 可重复输入动作

**定义**：在**真实主场景**里，用**可重复的 viewport 输入动作脚本**驱动，做**状态断言**并留**截图序列**。

### 最低证据清单
- [ ] 加载的是**真实主场景**（`app/main.tscn` / 等价入口），非 mock。
- [ ] 一份**可重复的 viewport 输入动作脚本**（注入真实输入事件，如 `InputEventMouseButton` / `InputEventScreenTouch` 按窗口像素坐标换算）。
- [ ] **状态断言**：对交互后的内部状态做断言（非仅「函数被调用」）。
- [ ] **截图序列**：动作前/中/后各截图，可回放。
- [ ] **连跑 3 次全 PASS**（排除抖动/竞态）。
- [ ] （布局类增补）在**≥2 种宽高比**下各跑一遍。

### 红线（不得勾完成）
- ❌ 用 `pressed.emit()` / 直接调用回调**自证**交互，绕过真实输入路径。
- ❌ 只有「被调用」日志、没有状态变化断言（例：开火类必须 `full→damaged→destroyed` 的真实状态转变，不接受「planner 被调用」）。
- ❌ 只跑 1 次、或 3 次中有一次不 PASS。

---

## L2 — 双端对照（终点门槛）

**定义**：**先**真源侧截图，**再**目标侧截图，**统一分辨率**归一化，写 `review.json` 并**强校验**。

### 证据清单与顺序（顺序不可颠倒）
1. [ ] **真源侧**（如 Swift 模拟器）按同一操作/同一初始状态截 `swift.png`。
2. [ ] **目标侧**（如 Godot）同操作截 `godot.png`。
3. [ ] 两侧统一到相同分辨率（如 2796×1290）后并排。
4. [ ] 写 `review.json`（含 case、操作序列、结论），用强校验脚本（如 `validate_ui_review.py`）通过。
5. [ ] 结论为 `accepted`。

### 增补要点（真实教训）
- **截图前对齐初始状态**：起点不同（如「无旧存档 / 有旧存档」）要各截一次。
- **真机路径优先**：能用真机渲染栈（显式设备/UDID）的不用桌面窗口近似。
- 分辨率换算须记录（含宽高比、缩放系数、截图 SHA）。

### 红线（不得勾完成）
- ❌ 先截目标侧再补真源侧（顺序颠倒）。
- ❌ 两侧分辨率不统一就下视觉结论。
- ❌ `review.json` 缺失或未过强校验，仅口头说「看起来一致」。
