# 证据与备注模板（可选，非强制）

> 用途：给「留痕」一个轻量格式。**验收是「灯」，不是「门」**——`done` 没有任何前置条件，
> 不强制证据、不比较等级、不卡住任何人。这里只是**想留痕时**的写法参考。
> 与 `task-breakdown.md` 的「验收/备注」列配合使用。

---

## 核心原则：灰度、快迭代优先

- **done 无前置**：任务记 `done` 不需要先挂证据，工具不会因缺证据而拒绝。
- **想留痕就写，不写也行**：证据/截图/日志路径是**给人看的自由备注**，不是给机器设卡的凭据。
- **漏了不算事故**：验收漏了没关系，本来也不指望一波做到完美——再规划、再派任务去补就好。
- **检测代替预防**：遗漏由 `reconcile` 软报告暴露（体检报告，不是闸门），暴露后重新规划即可。

> 卡住一个 agent 的代价，远高于漏掉一次验收。

---

## 留痕怎么写（示例）

备注是**自由文本**，用 `--note` 传；不必套格式，写清楚「怎么确认的、东西在哪」即可。

```bash
# 简单：一句话说明
python3 agentic_workflow/tools/task_state.py --root .agentic done P2-7 \
    --agent a1 --note "改完自测通过，改动见 commit abc1234"

# 想详细：把命令、退出码、产物路径都写进去
python3 agentic_workflow/tools/task_state.py --root .agentic done P1-3 \
    --agent a1 --note "verify.sh 退 0；截图 out/p1-3/（3 张）；对照 review.json 判定一致"
```

> 兼容旧写法：早期 `--evidence LEVEL:PATH` 仍可用，会被折叠成路径串并入备注显示——但**不做任何校验**。

## 可选留痕清单（想到什么写什么，全选或全不选都行）

- [ ] 做了什么、改了哪些文件（或直接给 commit hash）。
- [ ] 怎么自测的（命令 + 退出码，或手工操作步骤）。
- [ ] 截图 / 日志 / 产物路径（方便别人复查）。
- [ ] 已知遗留 / 没覆盖到的边角（留给下一轮规划）。

## 反例（不必追求，但知道就好）

以下是**项目自己的**实践，**不写进通用框架**——每个项目按需自定，不要当成普世标准：

- 有的项目要求「自动化测试真实退出 0」才算数（管道会掩盖退出码，得看 `$?`）。
- 有的交互类项目要求「真实场景 + 可重复输入 + 状态断言 + 截图序列」。
- 有的双端项目要求「真源侧先截、目标侧后截、统一分辨率并排」。

这些**是那个项目内部可以自己收紧的口径**，框架只提供留痕格式，**不替任何项目设门槛**。
项目如果确实想要更严的检查，自己在项目侧加工具/脚本即可，与本框架解耦。
